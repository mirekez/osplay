# Extreme CPU port and acceptance tests

Extreme runs native Extreme instructions generated by its LLVM IR backend.
The kernel, musl, BusyBox and Dropbear execute on the C++HDL CPU or its generated
SystemVerilog model. The host adapter transports Ethernet frames; the guest
handles ARP, ICMP, TCP and SSH. There is no DMA, foreign-ISA interpreter or host
application substituted for guest execution.

## Build and run

```sh
bash tests/extreme/run_all.sh --kernel-only
python3 tests/extreme/userspace.py --test process
python3 tests/extreme/userspace.py --test descriptors
python3 tests/extreme/userspace.py --test ssh --verilator
python3 tests/extreme/userspace.py --test ssh-shell
python3 tests/extreme/userspace.py --test ssh-shell --verilator
python3 tests/extreme/userspace.py --test tcp --multicore
bash tests/extreme/extreme_interactive.sh
bash tests/extreme/run_all.sh
```

The matching Make targets are `extreme-interactive-{ping,process,tcp,ssh}-test`;
use `EXTREME_TEST_FLAGS="--verilator --multicore"` to select those options.

Interactive startup includes loading the simulated RAM and executing the native
kernel, BusyBox and (with networking) Dropbear initialization. Expect several
minutes before `/ # ` appears; Verilator can take longer. For visible cycle updates and to skip rebuilding, run
`./tests/extreme/extreme_interactive.sh --no-build --progress`. Commands also run
at simulated CPU speed. `exit 0` shuts down the guest; Ctrl-C stops the simulator.
Interactive sessions have no automatic cycle or wall-clock limit. Set
`EXTREME_USER_TIMEOUT` to a positive number of seconds to request a time limit;
`0` (the default for interactive use) disables it. Automated tests retain their
cycle and time limits.
The UART shell has no controlling terminal, so its job-control warning is expected.
Guest UART boot messages announce memory setup, root filesystem mounting, network
initialization and the handoff to `/bin/sh /etc/init.d/rcS`. Each stage reports
completion, and initialization failures identify the stage before shutdown.

Interactive sessions use the universal TAP and print setup commands if its
socket, host address or permanent neighbor is missing. To reuse the
Extreme-named bridge with all three CPUs, run from `~/osplay`:

```sh
bash tests/network/build_tap.sh
export OSPLAY_TAP=tap-extreme
export OSPLAY_TAP_SOCKET=/tmp/extreme-ethgig.sock
sudo env OSPLAY_TAP="$OSPLAY_TAP" OSPLAY_TAP_SOCKET="$OSPLAY_TAP_SOCKET" \
  bash tests/network/start_tap.sh --background
python3 tests/network/tap.py extreme
bash tests/extreme/extreme_interactive.sh
```

Without those exports, the defaults are `tap-osplay` and `/tmp/osplay-tap.sock`.
The shared host address is `192.168.76.1/24`. The guest initializes its
fixed `192.168.76.2/24` address and `02:00:00:00:00:02` MAC automatically; no gateway
or guest `ifconfig` command is required. Dropbear starts on port 22. The launcher
prints a ping command and the complete patched-client SSH command, including the
shared OSplay identity. Wait for `OSPLAY:TCP_LISTEN 22` before connecting.

Extreme, Rocket and Tribe use the same test identity: `build/osplay_ssh_key`.
Fresh builds install the checked-in `tests/busybox/keys/osplay_ssh_key` fixture;
existing local identities are preserved. Every guest authorizes its public key.
The shared Dropbear-format client key is
`build/tests/busybox/dropbear-host/osplay_ssh_key.dropbear`. Extreme refreshes it
and the guest's authorized keys at startup, including with `--no-build`.
Old Extreme-specific `test_key` files are no longer used. Restart a running
guest to pick up the shared key.

Select another socket with `--tap-socket PATH` or `OSPLAY_TAP_SOCKET`.
`OSPLAY_TAP` selects the host interface; printed setup commands preserve these
settings through sudo. Guest IP and MAC are fixed in the image.
Use `--no-network` for a UART-only shell.
Old `EXTREME_*` TAP/address variables no longer select a separate link.
`tests/extreme/start_tap.sh` delegates to the universal helper; `make extreme-tap`
builds the shared bridge. Setup repairs an existing bridge without replacing it.
Keep the bridge running between CPUs, with only one active simulator at a time.
Automated ping/TCP/SSH tests use this shared link when `OSPLAY_TAP`,
`OSPLAY_TAP_SOCKET` or `--tap-socket` is supplied; otherwise they create a private
network namespace.

The shared-key regression verifies clean installation, preservation of an existing
local key, conversion and the authorized keys in a real ext4 guest image:

```sh
python3 tests/extreme/test_ssh_keys.py
```

The link regression uses the real TAP helper in an isolated namespace:

```sh
unshare -Urn python3 tests/extreme/test_interactive_network.py
unshare -Urn python3 tests/extreme/test_interactive_network.py --console
unshare -Urn python3 tests/extreme/test_interactive_network.py --console --verilator
```

The complete runner covers kernel boot and Ethernet, then userspace boot,
descriptor metadata, processes, ping, TCP and SSH, with one/three cores in C++ and
Verilator. These are instruction-level simulations of real applications and can
take considerable time. `--no-build` reuses compiled artifacts. User networking
automatically runs in a private `unshare -Urn` namespace with a TAP device. The host requires
`ip`, `ping`, `sysctl`, `/dev/net/tun`, and enabled unprivileged user namespaces.
An existing bridge can instead be supplied through `--tap-socket`.

`support/extreme/prepare.sh` builds the compiler and board, prepares the pinned
freestanding libc++ headers, and builds musl 1.2.5, the pinned BusyBox revision,
and Dropbear 2026.94. Package versions and hashes are in the preparation scripts.
LLVM/Clang 21 and C++HDL come from `CPPHDL_HOME` (default `~/cpphdl`). The CPU
checkout defaults to `tests/extreme/extreme_cpu`, a relative symlink to the sibling
Extreme CPU checkout. Scripts resolve it from their location, so they also work
when launched outside this directory. `EXTREME_CPU_HOME` remains an explicit
override. Rootfs
construction requires `mke2fs` and `debugfs`; it does not require a root mount.
The downloaded Dropbear copy receives the existing OSplay test patch. Package
stages are cached by their build inputs and rebuild objects when those change.

Userspace uses a 512-bit bus, SIMD enabled, two 32 MiB RAM banks and an MMIO bank.
The UART, timer, Ethernet packet buffers and shutdown device are implemented in
`extreme_cpu/devices`. Both flows share the board test harness. `--multicore`
adds two idle cores; the separate kernel multicore tests exercise actual task
issue and worker execution. Userspace processes currently run on core zero.

Artifacts and logs live under `build/tests/extreme`. Each acceptance invocation
creates a private ext4 rootfs and image, so guest writes do not affect another
run. Override `EXTREME_BUILD_ROOT`, `EXTREME_USER_TIMEOUT` (seconds, default 7200 for tests and 0 for interactive use),
`EXTREME_SCRATCH` (default `/dev/shm`), or `JOBS` as needed. Development runners
can select `EXTREME_BOARD_CPP`, `EXTREME_BOARD_SV`, `EXTREME_USER_IMAGE`,
`EXTREME_BRIDGE` and `EXTREME_SSH_CLIENT` explicitly.

## What the tests check

* Kernel: shared C++ containers/allocator, binary32 edge cases, task dispatch,
  real ARP and ICMP replies, and memory/MMIO stalls.
* Descriptor metadata: a small native musl fixture checks regular files, pipes,
  sockets and pseudo-terminals after redirecting fd0, including legacy stat64,
  `fstatat(AT_EMPTY_PATH)`, `ttyname()` and invalid-descriptor errors. PTY
  `fchownat` tests cover UID/GID changes, unchanged IDs, directory-relative and
  empty paths, stat consistency, invalid arguments, and Dropbear's root-ownership
  reset at logout (including a PTY already removed). Ownership changes are
  currently supported for live PTYs; regular filesystem nodes return `EROFS`.
* Process: inherited fd10, a three-stage pipe, fork/exec, parent/child environment
  isolation, exit status, nested `ls`, binary64 formatting, and signal delivery.
* TCP: a BusyBox `nc` listener executes a shell command received over Ethernet,
  writes a guest file, and exposes its contents through the guest UART.
* SSH: the guest Dropbear authenticates a test key and executes commands through
  BusyBox. The first session opens a pseudo-terminal for `tty` and nested `ls`;
  two more sessions verify that connections work after earlier sessions close.
  Host keys and credentials are isolated regression fixtures. The runner requires
  the expected output and successful client and CPU exit status.

The SSH configuration intentionally matches the Tribe test profile: the patched
client/server use the `none` cipher and the OSplay transcript-proof test path.
It is an interoperability regression, not production encrypted SSH. The kernel's
existing deterministic random source is likewise suitable only for this profile.

## Validated configurations

The completed port was checked with one-core descriptor, process, TCP and
three-session SSH acceptance tests in both C++ and Verilator. SSH includes the
PTY command, two reconnects and clean guest shutdown. The final SSH runs took
815,320,032 cycles in C++ and 815,438,263 in Verilator; host networking changes
packet timing, so these tests require successful behavior rather than identical
cycle counts. Three-core userspace boot passed both flows at 33,062,034 cycles.
The nine-case kernel matrix also passed. The full three-core userspace network
matrix is available in `run_all.sh` but was not part of this validation run.

CPU/compiler regressions passed with SIMD enabled (50 tests) and disabled
(48 tests), including both simulation flows. RTL synthesis and `check -assert`
passed, as did 95 OSplay host-test checks. Acceptance logs are under
`build/tests/extreme/results/userspace-<test>-c<cores>-<flow>/`.

## Native ABI and current limits

C packages use Clang's little-endian ARMv7 ILP32 frontend ABI to obtain 64-bit
`long double`, then LLVM bitcode is lowered to Extreme instructions. No ARM
machine code is accepted. Integer64 arithmetic and binary32/binary64 helpers
use 32-bit operations; no 64-bit ALU or FPU was added. Kernel C++ disables
exceptions and RTTI and uses the pinned exception-free libc++ subset.

Return addresses remain in register lanes. Native context save/restore preserves
the compiler's return registers, register SP, activation pointer and continuation.
Kernel and user activation storage are separate. Fork snapshots mutable globals,
allocated data and live activations; blocked system calls are replayed when a
process resumes. Signals are delivered at syscall boundaries; one-argument
handlers are supported and `SA_SIGINFO` is rejected. Scheduling is cooperative;
uncooperative CPU loops are not preempted. Native pthread creation is unsupported.

Executables are prelinked into the image. Rootfs `ECAPP` descriptors select the
native BusyBox or Dropbear entry and reset user globals during exec. This is not
a general ELF loader or dynamically linked userspace. The address space is flat,
without an MMU or process memory protection. Hardware return depth is 32 calls
for this profile; compiler activation bounds are checked at boot. Dynamic local
allocations have a checked 64 KiB arena per activation. These bounds are explicit
prototype limits, not a general hosted C/C++ runtime guarantee.
# Shared TAP

Interactive sessions now default to the universal `tap-osplay` bridge at
`/tmp/osplay-tap.sock`. See [shared TAP setup](../network/TAP.md) for setup,
checks, and reusing an existing bridge with `OSPLAY_TAP`/`OSPLAY_TAP_SOCKET`.
All three CPUs use host `192.168.76.1` and guest `192.168.76.2`.
Rebuild older Extreme images by running the launcher without `--no-build`.

The `ssh-shell` regression opens a login shell through a real host PTY, types
`ls` one character at a time, verifies echo before sending Enter, repeats file
listings, runs interactive `top -d 1`, waits for two screens without typing,
quits with `q`, verifies the shell still runs commands, and exits the SSH
session and guest cleanly. Extreme builds enable `FEATURE_TOP_INTERACTIVE`;
timed PTY polls preserve their absolute deadline while Dropbear runs, so `top`
refreshes even when no keys arrive.
The kernel PTY line discipline supplies canonical input, CR-to-LF translation,
echo, erase/kill and EOF handling; incomplete lines leave the shell parked while
Dropbear forwards their echo.
